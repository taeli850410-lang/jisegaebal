대상: Claude Code / Claude 웹 + GitHub + Vercel 짝 문서: 재개발닷컴_탐색모듈_개발명세서.md (= SSOT)

0. 명령 프롬프트에 "무엇을" 써야 하는가

AI에게 개발을 시킬 때 빠지면 반드시 사고 나는 6요소.

#	요소	안 쓰면 생기는 일
1	역할·목표	범위를 제멋대로 넓혀 3일치 코드를 한 번에 뱉음
2	기술 제약 (스택/버전/금지 라이브러리)	Next.js·Prisma·shadcn을 임의로 끌어옴
3	SSOT 참조 (명세서 어느 섹션인지)	필드명·enum이 매번 달라져 나중에 전부 충돌
4	산출물 정의 (파일 경로까지 명시)	코드가 채팅에만 뿌려지고 커밋 불가
5	완료 조건(DoD)	"됐다"의 기준이 없어 무한 수정
6	금지사항	잠금 필드를 프론트에서 blur만 하는 식의 치명적 구현

한 프롬프트 = 한 Phase = 한 PR. 이걸 어기면 리뷰가 불가능해집니다.

1. 마스터 프롬프트 (프로젝트 최초 1회)
너는 이 프로젝트의 리드 풀스택 개발자다.

## 프로젝트
한국 정비사업(재개발·재건축) 탐색 플랫폼. 재개발닷컴을 벤치마크하되
"권리분석·분담금 시뮬레이터"를 차별화 축으로 갖는다.

## 기술 스택 (변경 금지)
- Frontend: React 18 + Vite + TypeScript + Tailwind CSS + Zustand
- Map: 카카오맵 JavaScript SDK (JS 키만 프론트 노출, REST 키는 서버 전용)
- Backend: Vercel Serverless Functions (/api)
- DB: Supabase (Postgres 15 + PostGIS + RLS)
- Chart: Recharts
- 배포: Vercel (GitHub main 브랜치 자동 배포)

## 금지
- Next.js, Prisma, ORM 도입 금지 (Supabase JS client + raw SQL 사용)
- UI 라이브러리(MUI, shadcn, antd) 도입 금지 — Tailwind로 직접 구현
- localStorage/sessionStorage 사용 금지
- 잠금(멤버십) 필드를 클라이언트에서만 가리는 구현 금지 — 반드시 서버에서 마스킹
- 내가 요청하지 않은 Phase의 코드를 미리 작성하지 말 것

## 코드 규약
- 파일명: 컴포넌트 PascalCase.tsx, 그 외 camelCase.ts
- 모든 금액은 "원(bigint)" 단위로 저장, 표시 직전에만 억/만 포맷 변환
- 모든 필터 상태는 URL 쿼리에 직렬화 (공유 가능해야 함)
- 주석은 한국어, 변수·함수명은 영어

## SSOT
첨부한 `재개발닷컴_탐색모듈_개발명세서.md`가 유일한 정본이다.
스키마·enum·API 시그니처는 반드시 이 문서를 따르고,
명세와 충돌하는 판단이 필요하면 코드를 쓰기 전에 먼저 나에게 질문하라.

## 작업 방식
1. 내가 "Phase N 시작"이라고 하면 해당 Phase만 구현한다.
2. 구현 전에 만들 파일 목록을 먼저 제시하고 내 확인을 받는다.
3. 구현 후 완료 조건(DoD) 체크리스트를 스스로 검증해서 보고한다.
4. 명세서에 없는 결정을 했다면 그 목록을 마지막에 따로 알려준다.

지금은 아무 코드도 작성하지 말고, 명세서를 읽은 뒤
(1) 이해한 구조 요약 (2) 명세의 빈틈·모순 목록만 답하라.

### 집계 테이블 (배치 산출)

```sql
create materialized view mv_district_trade_rank as
select d.id district_id,
       count(*) filter (where t.contract_date >= current_date - 30)  cnt_30,
       count(*) filter (where t.contract_date >= current_date - 90)  cnt_90,
       count(*) filter (where t.contract_date >= current_date - 365) cnt_365
from districts d left join trades t on t.district_id = d.id
group by d.id;

create materialized view mv_district_view_rank as
select district_id,
       count(distinct visitor_id) filter (where viewed_at >= now() - interval '1 hour') v_live,
       count(distinct visitor_id) filter (where viewed_at >= now() - interval '7 days')  v_7d,
       count(distinct visitor_id) filter (where viewed_at >= now() - interval '30 days') v_30d
from district_views group by district_id;

-- 대지평당가 (최근 90일 다세대 실거래 중앙값)
create materialized view mv_district_land_price as
select district_id,
       percentile_cont(0.5) within group (order by land_price_per_pyeong) med_price,
       count(*) sample_cnt
from trades
where contract_date >= current_date - 90
  and building_type = '다세대' and land_price_per_pyeong is not null
group by district_id having count(*) >= 1;

-- 월별 시계열 (스파크라인 + 전월대비)
create materialized view mv_district_price_monthly as
select district_id, date_trunc('month', contract_date) ym,
       avg(land_price_per_pyeong)::bigint avg_price, count(*) cnt
from trades where contract_date >= current_date - interval '12 months'
group by 1,2;
```

**리프레시**: Vercel Cron
- `mv_district_view_rank` → 5분
- `mv_district_trade_rank`, `mv_district_land_price`, `mv_district_price_monthly` → 매일 04:00 KST
- 실시간 조회순만 정확도 요구 높음 → Upstash Redis `ZINCRBY viewrank:1h` 병행 권장

```ts
// api/_lib/gate.ts
const LOCKED = ['publishedPrice','initialCapital','landSharePyeong','exclusivePyeong','useApprovalDate','minBidPrice'] as const;
export function maskByTier<T extends object>(row: T, tier: Tier) {
  if (tier !== 'free') return row;
  return { ...Object.fromEntries(Object.entries(row).map(([k,v]) => [k, LOCKED.includes(k as any) ? null : v])), locked: true };
}
```
※ 잠금 필드를 **필터 조건으로 보낸 요청**은 free tier에서 400 반환(무시 아님).

## 6. 핵심 계산 로직

// 대지지분 평당가
landPricePerPyeong = price / landSharePyeong;

// 전월대비 (MoM)
momRate = (thisMonthAvg - lastMonthAvg) / lastMonthAvg * 100;
// 표기: 상승 ↑ red, 하락 ↓ blue (원본과 동일: 하락을 파란색으로)

// 억/평 포맷
formatEokPerPyeong(v) → v >= 1e8 ? `${(v/1e8).toFixed(1)}억/평` : `${Math.round(v/1e4).toLocaleString()}만/평`

// 억 포맷 (매물 최저가)
formatEok(v) → `${(v/1e8).toFixed(v % 1e8 === 0 ? 0 : 2).replace(/0$/,'')}억`  // 8.5억 / 6.35억

// 조회수 dedupe: 동일 visitor_id + district_id 1분 내 중복 무시
```

| 6 | 지역 필터가 4개 시도만 지원 | 전국 17개 시도 + 시군구 2depth |
| 7 | 실거래 카드에 지도 연동 없음 | 카드 hover → 지도 폴리곤 하이라이트 |
| 8 | 권리분석 없음 | **분담금 시뮬레이터 연결**(감정가 추정 → 비례율 → 분담금) ← 핵심 차별화 |

## 모듈 G. 지도 인라인 필터바 (Map Toolbar)

### G-1. 사업종류 (지도판)
패널 버전과 동일하되 **4번째 그룹이 추가**됨:
```
☑ 전체
☐ 민간주도: 재개발 / 신통기획 / 민간도심복합 / 재건축(단독주택) / 재건축(아파트) / 지역주택조합

☐ 소규모:  모아타운 / 가로주택 / 소규모
☐ 기타:    ● 가상구역          ← 신규 발견
```
🔑 **가상구역(Virtual District)** = 아직 지정되지 않았지만 사용자/운영자가 임의로 그린 예상 구역. 회색(●#6B7280). 정비구역 플랫폼의 "가상구역 그리기" 기능과 직결.

공시가 👑                            [전체]
0 ──────●──────────────●────── 10억
[전체*][~1억][1~2억][2~3억][3~4억][4~5억][5~10억][10억~]

- 공시가 슬라이더 눈금은 비선형(0 / 2억 / 5억 / 10억) — 로그 스케일.

### G-4. 좌측 레이어 탭 (Vertical Layer Switcher)

```
┌──────┐
│ 실거래 │  ← 실거래 마커
│ 매물  │  ← 매물 마커

🔑 **`단지` 레이어는 1차 캡처에 없던 신규 축** — 아파트 단지 정보(재건축 대상 단지)를 별도 관리.

# PART 4. 추가 개발 명세

## 10. 추가 데이터 모델

```sql
-- 가상구역 (사용자/운영자 그리기)
create table virtual_districts (
  id           bigserial primary key,
  owner_id     uuid references auth.users(id),   -- null = 운영자 공식 가상구역
  name         text not null,
  memo         text,
  geom         geometry(MultiPolygon, 4326) not null,
  area_m2      numeric generated always as (st_area(geom::geography)) stored,
  visibility   text default 'private',           -- private/public
  parcel_count int,                              -- 포함 필지 수(집계)
  created_at   timestamptz default now()
);
create index on virtual_districts using gist(geom);

-- 아파트 단지 (레이어 4번째)
create table complexes (
  id bigserial primary key,
  kapt_code text unique,                -- K-apt 연계
  name text not null,
  district_id bigint references districts(id),   -- 정비구역 편입 여부
  address text, centroid geometry(Point,4326),
  built_year int, total_households int, total_dong int,
  far numeric, bcr numeric,             -- 용적률/건폐율 (재건축 사업성 핵심)
  land_area_m2 numeric,
  avg_land_share_pyeong numeric         -- 세대당 평균 대지지분
);

-- 커뮤니티
create table posts (
  id bigserial primary key,
  author_id uuid references auth.users(id),
  district_id bigint references districts(id),   -- 구역 태그
  body text not null,
  image_urls text[],
  like_count int default 0, comment_count int default 0,
  hot_score numeric default 0,                   -- 인기글 랭킹
  status text default 'visible',                 -- visible/hidden/reported
  created_at timestamptz default now()
);
create index on posts (district_id, created_at desc);
create index on posts (hot_score desc);

create table post_comments (
  id bigserial primary key, post_id bigint references posts(id),
  author_id uuid, body text, created_at timestamptz default now());

create table post_reactions (
  post_id bigint, user_id uuid, kind text default 'like',
  primary key (post_id, user_id, kind));

-- 소유주 인증
create table ownership_verifications (
  id bigserial primary key,
  user_id uuid references auth.users(id),
  district_id bigint references districts(id),
  address text, jibun text,
  proof_type text,          -- registry_pdf / tax_bill / manual
  proof_url text,
  status text default 'pending',   -- pending/approved/rejected
  reviewed_by uuid, reviewed_at timestamptz,
  created_at timestamptz default now()
);
-- 승인 시 posts 렌더링에 🔵소유주 뱃지 부여

-- 콘텐츠 수집 (고시/공고 · 보도자료 · 뉴스 · 블로그 통합)
create type content_kind as enum ('notice','press','news','blog');
create table contents (
  id bigserial primary key,
  kind content_kind not null,
  source text not null,           -- '서울시 금천구' / '한국경제' / '청카이브'
  source_group text,              -- 탭 그룹: 서울/경기/인천/부산, 서울시/국토부/부동산원
  sub_kind text,                  -- 고시 / 공고
  title text not null,
  summary text,
  url text unique not null,
  thumbnail_url text,
  published_at timestamptz not null,
  district_ids bigint[],          -- NER로 추출한 연관 구역
  raw_hash text,
  created_at timestamptz default now()
);
create index on contents (kind, source_group, published_at desc);
create index on contents using gin (district_ids);

-- 통합 검색 인덱스
create extension if not exists pg_trgm;
create table search_index (
  id bigserial primary key,
  kind text not null,             -- district / address / station / complex
  ref_id bigint,
  label text not null,            -- '상도15' / '동작구 상도동 123' / '상도역'
  sub_label text,                 -- '신통기획 · 시공사선정'
  centroid geometry(Point,4326),
  weight int default 0
);
create index on search_index using gin (label gin_trgm_ops);
```

## 12. 추가 API

| Method | Endpoint | 설명 |
|---|---|---|
| GET | `/api/search?q=` | 통합 검색 (구역/주소/역/단지), trigram 유사도 + weight 정렬, 각 kind별 상위 5 |
| GET | `/api/map/features?bbox=&layer=district\|trade\|listing\|auction\|complex&filters=` | 지도 뷰포트 피처 (GeoJSON, 줌 레벨별 클러스터링) |
| GET | `/api/complexes?bbox=` | 단지 레이어 |
| CRUD | `/api/virtual-districts` | 가상구역 생성/조회/수정/삭제 (PostGIS geom) |
| GET | `/api/posts?tab=latest\|hot\|my-area&districtId=&cursor=` | 커뮤니티 피드 |
| POST | `/api/posts` · `/api/posts/:id/like` · `/api/posts/:id/comments` | 작성/반응 |
| POST | `/api/verify-ownership` | 소유주 인증 신청(파일 업로드) |
| GET | `/api/contents?kind=&group=&cursor=` | 고시공고/보도자료/뉴스/블로그 |
| POST | `/api/feedback` · `/api/ad-inquiry` | 의견 보내기 / 광고 문의 |

### 지도 피처 API 성능 규칙
```
zoom ≤ 12 : 시군구 단위 집계 마커 (구역수만)
zoom 13-15: 구역 centroid 마커 + 클러스터
zoom ≥ 16 : 폴리곤 실도형 + 개별 매물/경매 마커
→ ST_Simplify(geom, tolerance) 줌별 사전 생성 컬럼(geom_z13, geom_z16) 권장
```

## 13. 상태 동기화 — 지도 툴바 ↔ 패널

두 필터 UI가 **같은 store를 바라보되 노출 옵션만 다름**.

```ts
// 유형 매핑: 지도 3분류 ↔ 패널 6분류
const TYPE_GROUP_MAP = {
  공동주택: ['villa', 'apt', 'presale'],
  단독주택: ['house'],
  기타:     ['land', 'etc'],
} as const;
// 지도에서 '공동주택' 선택 → store.listing.types = ['villa','apt','presale']
// 패널에서 'villa'만 해제 → 지도 '공동주택' 칩은 indeterminate(부분선택) 표시
```
→ `FilterChip`에 `state: 'off' | 'partial' | 'on'` 3상태 지원 필수.

## 15. Phase 재편 (P1~P12)

| Phase | 범위 |
|---|---|
| P1~P8 | (PART 2 동일) 스키마 → 랭킹 → 패널 → 실거래 → 필터/매물 → 경매/관심 → 게이팅 → 분담금 |
| **P9** | 지도 인라인 툴바 + 레이어 4종(실거래/매물/경매/단지) + 뷰포트 피처 API |
| **P10** | 가상구역 그리기(PostGIS) + 필지 집계 + 저장/공유 |
| **P11** | 콘텐츠 수집 파이프라인(고시공고·보도자료·뉴스·블로그) + SEO 랜딩 |
| **P12** | 커뮤니티 + 소유주 인증 + 앱(TWA/PWA) + 광고 문의·데이터 출처 푸터 |

**순서 근거**
- P11(콘텐츠)은 **개발 난이도 대비 SEO 효과가 가장 큼** → 트래픽이 급하면 P9보다 먼저 당길 것.
- P12(커뮤니티)는 유저 없이는 빈 껍데기 → 트래픽 확보 후 착수. 단, **소유주 인증**은 우리만의 차별화라 초기에 설계는 확정해둘 것.
